Shard Changelog — Consolidated Summary

Barding (Peacemaking / Provocation / Discordance)

Bugs found and fixed in existing shard code

  • BaseAI.DoBardProvoked() only cleared BardProvoked if the bard was gone/out of range — the custom ProvokeTimers expiry cleared Combatant/Warmode but left BardProvoked true, causing instant re-provoke. Fixed by also clearing BardProvoked, BardMaster, BardTarget in that expiry callback.
  • BaseCreature.Provoke() hardcoded BardEndTime to +30s regardless of the calculated duration (the custom ProvokeTimers table was the real authority anyway).
  • DoBardPacified() confirmed clean — no fix needed.

Bard Break mechanic — complete and confirmed working

  • Grace window after a successful peace/provoke, then a 2s tick that rolls barding vs. mob difficulty for a chance to break free.
  • Grace window: 5s → 3s; does not restack on re-barding — only granted on first entering control or after a break.
  • Post-break immunity: 5s flat (per-mob knob available for higher-tier mobs).
  • On break: overhead message "Regains Focus" + sound 0x1E3 (matches Night Sight cast sound).
  • Confirmed working via live test and a fresh server restart — an earlier "breaks were off until debug toggled" report turned out to be a false correlation (Debug only ever controlled message spam, never the hardcoded-true Enabled flag).
  • Observed peace-chance variance on "the same" mob (e.g. a Balron shifting 50%→37% between tests) traced to per-spawn HitsMax differences feeding GetBaseDifficulty() — not a bug.

Magic Instrument loot system (new)

  • InstrumentGrade enum (Normal/Surpassingly/Eminently/Exceedingly/Supremely) — flat bard-skill bonus via GetDifficultyFor (0/2/5/8/12), drop odds scaled by the dying mob's Fame/difficulty (near-never Supremely on weak mobs, up to 50% on the hardest).
  • InstrumentDurability enum (Normal/Durable/Substantial/Massive/Fortified/Indestructible), +100 max uses per tier, rolled independently of Grade.
  • Composed magic-item names (e.g. "a massive supremely harmonious lute"); "Harmonious" used in place of "Accurate" for grade wording.
  • Drops tuned generous on request: Indestructible 1%→3%, mundane Normal 55%→30%; low-end Grade table loosened from 85% Normal/0% Supremely to 50%/2%. Base instrument uses bumped +300 across the board.
  • Added BonusBardSkill field for uniques exceeding Supremely's +12 cap.
  • First named unique: Fantasia (Lute, +20 BonusBardSkill, 3000 uses, deep purple hue) — 0.05% from top-tier/red-named mobs, 3% from champion spawn bosses, gated independently of normal loot rolls.

Taming (Custom Pet System)

Goal: Role-based controllable pets (Tank / Ranged / Melee) built on the Insidious Dungeon ability framework, with kill-based AnimalTaming skill gain.

Ability cooldown/trigger-chance refactor

  • CustomAbility.cs now supports settable trigger chance/cooldown (SetTriggerChance()/SetCooldown()), persisted via serialization. All 30 ability subclasses updated — shared defaults kept at original values so Insidious Dungeon's locked mobs weren't retuned; tightened cooldowns applied per-pet at construction instead.

Pet roster — now 14 pets total

  • Tank: EmberWarden, Goatox (Charge removed after aggro conflicts with other Charge-using mobs — replaced with real Taunt + PetClass.Tank passive healing).
  • Melee: Bloodfang, plus 8 elemental generalist pairs (Frostmaw/Icefang, Venomcoil/Toxifang, Grimwyrm/Direfang, Sunwyrm/Sunfang) — left unclassified (PetClass.None) for now.
  • Ranged/Caster: TempestDrake, Mysticwyrm, Sagefang — Int-scaled, low-HP tradeoff, fully non-mana-dependent by design.
  • Repeated CanFly = true-in-constructor mistake (get-only override) caught and fixed multiple times across the roster before shipping.
  • Venomcoil/Toxifang (deliberately the highest-damage elemental pair) rebalanced via -35% HP instead of a damage nerf, keeping their damage identity intact.

Leveling / stat system

  • Isolated into a new TamingCreature : AbilityCreature subclass rather than polluting shared AbilityCreature.cs (same mistake class as the earlier ability-cooldown-defaults issue, caught one level up the hierarchy).
  • 20 unspent points per level (loosened from 1) + XP/level-up system messages.
  • Respec: PetRespecStone.cs, consumable, unlimited uses, refunds Str/Dex/Int, LootType.Blessed. Shard-wide drop hook added to BaseCreature.GenerateLoot(), scaled by Fame (~0.35% weak → 5% cap around dragon-tier).
  • Bug fixed: Stam/Mana collapsed to 1 on the first Dex/Int point spent — SetStam/SetMana were never called (unlike SetHits), leaving the seed at 0 and falling back to a getter that broke the instant the seed left 0. Fixed centrally in TamingCreature.SpendPoint() for the whole roster (present and future pets).
  • Int-scaling wiring bug: pets used AddCustomAbility instead of the Int-scaling AddScalableAbility hook, making Int investment dead code — fixed roster-wide. EmberWarden's high base Int (backwards from "Int rewards Ranged" intent) still flagged, unresolved.
  • New PetClass enum (None/Tank/Ranged/Melee), version-gated serialization. Only Tank has real mechanics so far: healing bonus via Mobile.Heal()'s OnHeal hook, raised from +20% → +60% total on request. AnimalLoreGump.cs shows a Class row when set.

Movement / AI — extensive iteration

  • Fixed pet speed, follow-run-threshold, and Recall teleport for unbonded pets (Dex-based speed scaling shard-wide, a fragile range-scan in TeleportPets, and an onlyBonded=true flag blocking unbonded pets).
  • Kiting root cause: MageAI.RunTo() only retreats when SmartAI (gated by MagicalAbility.MageryMastery, distinct from plain Magery) is true — none of the ranged pets had it set. Added MageryMastery to all three.
  • Found RangeFight hardcoded to 1 (melee range) on all ranged pets, so they always closed to melee first — raised to 8, then narrowed to 4 after overcorrection (pets fleeing to max range), then finally replaced with a custom NoCastMageAI.RunTo() override: approach to RangeFight and hold, never retreat, positioning fully tamer-command-driven. RangeFight raised back to 10 once retreat was structurally impossible.
  • Closed two real teleport-spell leaks (DoActionCombat's teleport branch — reachable due to Core.SA/Core.TOL being true on this shard, not blocked by low Magery as first assumed; and OnFailedMove's unconditional 10% teleport-when-stuck roll) via NoCastMageAI forcing CheckCanCastMagery() false — also guarantees these pets never depend on mana at all.
  • LOS bug found: none of the 30 custom ability files checked line-of-sight (pure spatial radius), causing abilities to hit through walls and cause "unprovoked" aggro in adjacent rooms. Fixed by adding an LOS check to the shared IsValidAbilityTarget helper (covers 12+ files at once), plus 3 files with their own inline dual-branch filters (FlameStrikeCone, FlameStrikeLine, ForkedFlameStrike). Not yet audited: Fear.cs, HealAllies.cs, ToxicSpores.cs, TempestItem.
  • Mage pet damage buffed twice on feedback: +18%, then a further +15% stacked on top (final: TempestDrake Zap 13-17/BarrageOfBolts 14-20/Thunderstorm 9-15; Mysticwyrm FlameStrikeTargeted 17-24/FlameStrikeLine 20-24/ForkedFlameStrike 22-28; Sagefang FlameStrikeTargeted 15-21/Firebolt 8-14).
  • Sagefang still felt weak after both buffs but explicitly should never exceed Mysticwyrm — fixed by giving it a 3rd ability (Zap, 10-15, 6s cd) instead of inflating existing numbers, since it was stuck at the drake-tier 2-ability convention while TempestDrake (also drake-tier) already had 3.

Friendly-fire bug (systemic, shared with Insidious Dungeon abilities)

  • 12 AOE ability files shared a wild-caster-only targeting filter that didn't account for a tamed caster hitting its own owner/sibling pets. Added shared IsValidAbilityTarget() helper, patched 10 files; 2 confirmed pre-existing real bugs (ToxicRain/Thunderstorm hitting sibling pets). Root cause of the originally reported Sunwyrm/MeteorStrike self-damage bug remains unresolved — lives in the unaudited companion MeteorItem class.

New abilities & commands

  • Taunt.cs — new CustomAbility (8 range, 0.5 trigger, 15s cooldown, 6s hold): forces a target to attack the caster via a recurring 1s Timer that re-asserts Combatant/FocusMob (a single assignment doesn't hold since AI re-evaluates each tick). Not added to the shared 30-ability registry array since every pet instantiates directly. Wired into Goatox (its real replacement for the removed Charge) and EmberWarden (added as a genuine 3rd ability alongside Grapple, which was renamed from taunt to pull to avoid confusion).
  • PetPull ([PetPull], player-usable): 3-second overhead countdown, then calls the same TeleportPets method Recall.cs uses. Later refactored into a shared static DoPetPull() so both the command and a new right-click context-menu entry call the same code.
  • [dip (emergency escape) now also instantly pulls pets to the same destination (no countdown, unlike PetPull) by calling TeleportPets directly after the player's own teleport.
  • (tameable) tag added shard-wide (not just custom pets) — BaseCreature.cs's AddNameProperties/OnSingleClick, gated on !Controlled && Tamable && Alive, following the exact existing (summoned)/(bonded)/(tame) pattern. Applies automatically to every tameable creature on the shard.

Admin tooling

  • PetAdminGump.cs ([PetAdmin]): Str/Dex/Int/Level/XP/UnspentPoints direct-set + instant respec button, links to SetSkillGump. PetLevel setter now correctly grants points-per-level even when set directly via [props.
  • CustomAdminLauncherGump.cs ([MooseAdmin]): shortcut launcher; restructured to support a "Spawn Tools" header with indented sub-buttons (Insidious Spawner, Pets).
  • PetSpawnGump.cs ([PetSpawn]): lists all 14 pets, resolves type by name via ScriptCompiler.FindTypeByName (one-line addition for future pets), spawns and auto-assigns to a targeted owner, sets ControlOrder=Follow by default.
  • Standing convention: every new custom gump gets a shortcut added to CustomAdminLauncherGump.cs as part of delivery.

World Building — Insidious Dungeon (Custom Undead/Demon Mob Roster)

Roster overview — now 32 mobs (all on Massapequa's Custom Abilities 3.0 framework)

  • Undead wing (tiers 1–5): GraveWarden, HollowWraith, InsidiousLich, DeathElemental, SepulcherDragon (dungeon boss — renamed from a name colliding with ServUO's stock SkeletalDragon).
  • Demon/gargoyle wing (tiers 6–8): BoundGargoyle, AbyssalDrake, Wyrmlord.
  • Daemon wing (tiers 9–11): CinderBrute (renamed from PitFiend — stock collision), InfernalDaemon, Doomlord (renamed from Archdaemon after it turned out ServUO ships its own stock Archdaemon class that silently absorbed [add archdaemon, causing a long-running low-gold mystery eventually root-caused via grep).
  • Gargoyle mini-pack (siblings to BoundGargoyle, same power band): GraniteGargoyle, StormwingGargoyle, DreadwingGargoyle, RuneboundGargoyle.
  • 17-mob medium-tier expansion (same difficulty band as GraveWarden/GraniteGargoyle/CinderBrute, +100g/~10% more HP), built on specific body IDs — all renamed after discovering the original flavor names were literal UO client body-graphic names (a second, distinct collision risk): Chitterfang, Gorgemaw, Stitchbrute, Rendclaw, Thornreaper, Marrowfiend, Grimjaw, Nightward, Umbralurker, Bloodmaul, Scorchguard, Rotswarm, Riftcaller, Nightthrone, Chasmborn, Gloomstalker, Veilrender.
  • Body-type sprite swaps: HollowWraith → 748, InsidiousLich → 747 (moving off placeholder bodies toward extracted real UO sprite art).

Recurring naming-collision lesson

  • Standing practice: grep Scripts/ for class <Name> before shipping any new mob — ServUO's stock bestiary (Pit Fiend, Daemon, Balron, Skeletal Dragon, Archdaemon) is the recurring collision risk, sometimes silent (no compile error, silently resolves to the stock class) rather than obvious.

Design philosophy settled

  • Base melee/spell damage is the real threat; custom abilities are low-damage visual spectacle, not primary damage.
  • Avoid abilities that lock the player out of control (cataloged: IcePrison, Snare, Zap, ThrowBoulder).
  • Positional/avoidable zone abilities (e.g. RagingTempest's persistent vortex) confirmed as a favorite, keeper pattern.
  • Heavy poison effects reserved for flavor-specific use only, not a general difficulty lever.
  • Rejected reverse-engineering GetBaseDifficulty() for stat design — build for "fun and fightable" first.

Loot system — long iterative history, now settled

  • Root-caused and fixed a shard-wide double-gold-drop bug (GenerateLoot() firing twice; unguarded PackGold paid out both times).
  • Fixed a structural gap: none of the roster's original loot packs included any weapon/armor pool at all.
  • Went through several generosity passes (tiering upgrades, then a same-tier-repeat approach for more item rolls) before adopting the stock Balron pattern as the final approach: layering two different pack tiers with no explicit PackGold at all —
  • entry tier = Average×2 + Meager×1
  • upper-mid tier = Rich×2 + Average×1
  • top tier (Wyrmlord/SepulcherDragon/Doomlord) = FilthyRich×2 + Rich×1
  • SepulcherDragon further boosted to FilthyRich×3 + Rich×2 as the true dungeon boss, now visibly outclassing its tier-mates.
  • UltraRich deliberately held in reserve for a future power-creep ceiling mob.
  • Discussed (and paused, pending concrete before/after examples) a proposal to give Insidious Dungeon mobs better treatment from the shard-wide loot sanitizer via a virtual property, without breaking its unified block-list.

Shard config fixes discovered along the way

  • Global HP multiplier confirmed at 1.4x; GetBaseDifficulty() divisor already matched.
  • ResistanceType has no Holy member — fixed a mob (RuneboundGargoyle) that mistakenly used it, mapped to Energy instead.
  • Notoriety: AlwaysMurderer added to the two true bosses (red-named), AlwaysAttackable to the rest (grey-from-spawn), since humanoid-bodied mobs otherwise spawn blue/innocent by default.
  • Full 30-ability sweep for a virtual/override mismatch bug — 3 of 30 abilities were wrong and patched.
  • Framework patch to CustomAbilitiesList.cs/AbilityCreature.cs/SummonMinion.cs made the ability pool reusable across mobs (previously capped near 1 use per ability class); save/load round-trip verified working after a server restart.
  • Second compile error class found on the daemon wing: CanFly/CanRummageCorpses/PoisonImmune are get-only overridden properties (matching stock Daemon.cs), not settable — fixed across CinderBrute/InfernalDaemon/Archdaemon.
  • Daemon wing hues corrected against a real numbered hue chart after two wrong initial picks (one invalid slot, one wrong tone): CinderBrute 342, InfernalDaemon 1258, Archdaemon/Doomlord 1157.

Testing status

  • InsidiousLich and GraveWarden: locked/perfect.
  • DeathElemental: very good, damage possibly slightly high, more testing planned.
  • HollowWraith: still a bit hot on damage — all early testing used a character with no Magic Resist, retest pending.
  • BoundGargoyle/AbyssalDrake/Wyrmlord: tested, generally positive (Wyrmlord's HP raised 440-520 → 530-620 after feeling low for its loot).
  • SepulcherDragon: tough for melee but became manageable once Aether was maxed — read as confirmation the shard's Aether systems work as intended for PVE.
  • Daemon wing: tested lightly, damage a bit high, deferred retuning to higher-end character testing.
  • Gargoyle mini-pack and 17-mob medium-tier batch: built, not yet tested.
  • Planned test matrix: Magic Resist + Parry character, and a bard using Discord with no Magic Resist.
  • Interested in custom high-end loot (armor sets, named weapons) down the line, deferred for now.
